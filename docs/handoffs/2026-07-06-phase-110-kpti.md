## What landed — A.1 (this PR)

The **user-half PML4 builder** + a **boot self-test**, with `KPTI_WIRED` still
`false` (the live CR3 is untouched; every existing gate unaffected).

- **`kernel/src/mm/kpti.rs`** (new). `self_test()` (called unconditionally from
  `mitigations::init_bsp`, inside `without_interrupts`) builds a real user PML4:
  a synthetic user page at `USER_VADDR_MIN`, plus a representative **minimal
  entry set** mapped through *fresh private sub-tables* at their existing kernel
  VAs — the `PerCoreData` page(s), the `syscall_entry` text page, and a fresh
  entry stack. It walks the table back and feeds every present leaf's
  `(role, present)` to `kernel_core::kpti::check_user_half_invariant`, emitting
  `KPTI_SELFTEST:PASS`. Frees leak-free (a `RecordingAlloc` tracks exactly the
  private table frames created; the real kernel pages the entry set *points at*
  are never freed).
- **Gate** `kpti-selftest-smoke` (`M3OS_KPTI_REGRESSION=1`, `xtask` +
  `.githooks/pre-push`): boots the stock kernel, asserts `KPTI_SELFTEST:PASS`.
  Runs in ~7 s. Also documented in `docs/appendix/regression-gates.md` + the
  `AGENTS.md` gate table.
- **Proven at boot:** `KPTI_SELFTEST:PASS user_pml4=… entry_set=6 leaves; no
  kernel-secret leaf reachable from user CR3` (6 = PerCoreData spans 4 pages +
  text + stack).

**What A.1 deliberately did NOT do:** wire the builder into
`new_process_page_table` / `AddressSpace` per-process. That only earns its keep
once the CR3 switch consumes the pair; building an inert second PML4 for
every fork/exec while `KPTI_WIRED=false` is pure overhead. The `mm::kpti`
builder is the reusable piece the wiring (now A.3) calls.

  user RSP to `gs:[user_rsp]`, spills `rax` → `gs:[kpti_scratch]`, loads
  `gs:[kpti_kernel_cr3]` → `mov cr3`, restores `rax`, and `jmp`s into the

  drift). Pre-switch instructions touch ONLY `gs:[…]` + registers (audited).
- **KPTI-aware sysret tail** (shared): after `pop rcx`, spill `rax` →

  pair retarget correct and costs production two gs-moves + a never-taken

  the whole tail; the NMI window is A.3's paranoid path.
- **`.text.kpti_entry` section**: the whole entry surface (both stubs + body +
  tail) is page-aligned (`.balign 4096` both ends) and bounded by

  text; the self-test asserts both stubs live inside it

- **LSTAR selection** — `lstar_target()` on `mitigations::state().kpti_active`:

## Load-bearing facts (learned mapping the kernel — do not re-derive)

1. **m3OS never executes `swapgs`.** `GS_BASE` is set directly to `PerCoreData`
   and stays that way in ring 3 (no FSGSBASE, no ring-3 `wrmsr`). The entry asm
   reads `gs:[OFFSET]` with **no swap**. Two consequences:
   - The `PerCoreData` page(s) **must** be in the user-PML4 entry set — the KPTI
     entry asm reads `gs:[kpti_kernel_cr3]` / `gs:[kpti_scratch]` *before* the
     CR3 switch. Already fields on `PerCoreData` (`kernel/src/smp/mod.rs:376–382`,
     offsets `smp::offsets::KPTI_{KERNEL_CR3,USER_CR3,SCRATCH}` at `:862–864`,
     zeroed today, read by nobody yet).
   - No swapgs ordering hazard — simpler than Linux.
2. **VA layout** (for the classifier / entry-set build):
   - User pages: `PML4[0]`, VA `0x200000 .. 0x0000_8000_0000_0000`.
   - Kernel image: PIE, relocated by a **fixed 1 TiB** (`0x10000000000`) → in the
     **lower half** at `PML4[2]`. (Same 1 TiB fact the Phase 111 kgdb gate uses.)
   - Heap: `0xFFFF_8000_0000_0000` = `PML4[256]`.
   - Kernel stacks: `0xFFFF_8080_0000_0000` = `PML4[257]` (`task/kstack.rs`).
   - Direct map: `phys_offset()`, some upper-half slot (compute at runtime).
3. **`mapper_for_frame(frame)`** (`mm/mod.rs:619`) builds an `OffsetPageTable`
   over an arbitrary PML4 through the direct map **without switching CR3** — the
   tool for populating the user PML4 from the BSP. `paging::get_mapper()` +
   `Translate::translate_addr` does VA→phys (scope it before building the user
   table to avoid two live `&mut PageTable` aliases).
4. **Three CR3-write loci** must all set the pair consistently once live:
   scheduler dispatch (`task/scheduler.rs:~5549`), `execve`
   (`syscall/mod.rs:~5715`), fork trampoline (`process/mod.rs:~2203`).
5. **QEMU default boot activates KPTI once `KPTI_WIRED` flips.** The `[sec]` line
   shows `kpti(policy=true active=false)` under `Auto` because QEMU reports
   `rdcl_no=false`. So the moment A.4 sets `KPTI_WIRED=true`, **every** default
   gate runs the trampoline. Great coverage — but it means A.2/A.3 must be
   correct before A.4, or all gates triple-fault. Consider gating activation
   behind `M3OS_MITIGATIONS=full` during bring-up so the default `auto` gates
   stay off KPTI until the trampoline is proven, then remove the gate.
6. **GLOBAL-bit guard already holds** (`count_global_kernel_leaf_ptes()==0`,
   asserted in `init_bsp`). Keep it; never introduce `CR4.PGE` while KPTI is on.

## What landed — A.3a (`feat/phase-110-kpti-a3a`, stacked on A.2)

The **full interrupt-delivery entry set + reachability validation**, still
inert (`KPTI_WIRED=false`):

- **Entry set grew to GDT + IDT + TSS.** On a ring-3 → ring-0 interrupt the CPU
  reads the IDT gate, the GDT descriptor for the target CS/SS, and TSS.RSP0 —
  all through the *active* (user) paging, before any handler runs. Missing any
  → delivery-time `#DF` → triple fault. `mm::kpti` now maps all three at their
  live linear addresses (`sgdt`/`sidt` for GDT/IDT; `gdt::tss_extent()` for the
  BSP TSS). New `push_kernel_range` helper (page-splits + de-dups shared pages,
  e.g. GDT+TSS adjacency).
- **Reachability round-trip** (`translate_in`): the self-test now manually
  walks the built user PML4 and asserts every entry-set page translates to the
  *same* frame the kernel map resolves — proving the trampoline's whole working
  set is present, not just that nothing extra leaked. New failure sentinel
  `KPTI_SELFTEST:FAIL reason=entry-set-unreachable`.
- **Flag split** `RX`/`RW` (entry text executable r/o; data pages NX r/w).
- **Isolation caveat — the A.3b hardening.** GDT/IDT/TSS are ordinary un-page-
  isolated kernel statics, so mapping their pages also exposes adjacent
  `.data`. Small, bounded, but a real residual Meltdown surface. A.3b must
  relocate the interrupt-delivery structures into a page-aligned entry section
  (Linux `cpu_entry_area`) — it's also the first consumer that makes the
  isolation load-bearing. Documented in the `mm::kpti` module header + tasks.
- **Green:** `check`, `kpti-selftest-smoke`.

## What landed — A.3b part 1 (`feat/phase-110-kpti-a3b`, stacked on A.3a)

The **reusable per-process user-half builder**, inert:

- **`mm::kpti::build_user_half(kernel_pml4_phys, kstack_top)`** — the function
  A.4 will load as the ring-3 CR3. Allocates a user PML4, shares `PML4[0]` with
  the kernel half (so mmap/brk/stack stay in sync — same frame, not a copy),
  and maps the entry set + this process's kstack top page through fresh private
  sub-tables (leak-free rollback on partial failure).
- **`mm::kpti::free_user_half`** — frees the private entry-set sub-tables + top
  frame; never `PML4[0]` (shared, freed by `free_process_page_table`) nor any
  leaf.
- **`collect_entry_pages`** — the shared entry set, now iterated **per online
  core** (each core's PerCoreData + GDT + TSS via
  `PerCoreData::entry_struct_extents`, BSP falling back to the global GDT/TSS)
  + the shared `.text.kpti_entry` + IDT. A process can run on any core, so all
  online cores' interrupt-delivery structures are mapped.
- **Design refinement — kstack top page instead of a separate per-CPU entry
  stack.** The CPU pushes the ring-3 IRQ frame to RSP0 on the user CR3; RSP0 =
  the process kstack top, so mapping just that **one top page** into the user
  half suffices (the stub switches to the kernel CR3 — which maps the whole
  kstack — before touching anything below it). No per-CPU trampoline stack, no
  frame relocation. Trade-off: it exposes ~4 KiB of the process's own kstack to
  itself (a small self-leak) — hardened later with a dedicated trampoline stack.
- **Self-test** now builds a real user half via `build_user_half` over a
  synthetic kernel PML4 and frees via `free_user_half` — validating the exact
  production path, not a test-only table.

**Remaining A.3b (part 2): the live IRQ/IST asm** per the blueprint below, plus
wiring `build_user_half` onto `AddressSpace` (A.4 consumes it).

## Blueprint — A.3b(part 2)–A.5 (in order; A.2 + A.3a + A.3b-pt1 ✅)

### A.2 — syscall-entry CR3 trampoline (`arch/x86_64/syscall/mod.rs`) ✅

The `syscall_entry` `global_asm` (`:1132–1314`). SYSCALL does **no** automatic
stack/CR3 switch, so the stub owns everything — no trampoline stack needed for
this path (nothing is auto-pushed):

```asm
; entry: user CR3 active, rcx=user rip, r11=user rflags, rax=syscall nr, no swapgs
mov gs:[OFF_USER_RSP], rsp          ; PerCoreData is user-mapped → OK on user CR3
mov gs:[OFF_KPTI_SCRATCH], rax      ; spill syscall nr (PerCoreData writable, user CR3)
mov rax, gs:[OFF_KPTI_KERNEL_CR3]
mov cr3, rax                        ; → kernel CR3 (PerCoreData mapped in BOTH halves)
mov rax, gs:[OFF_KPTI_SCRATCH]      ; restore syscall nr
mov rsp, gs:[OFF_STACK_TOP]         ; NOW safe: real kstack (PML4[257]) is kernel-only
… existing body …
; exit tail (after `mov rsp, gs:[OFF_USER_RSP]`, before sysretq):
mov rax, gs:[OFF_KPTI_USER_CR3]     ; but rax holds the return value → spill/restore via scratch
mov gs:[OFF_KPTI_SCRATCH], rax … mov cr3, …  ; → user CR3, then sysretq
```
- **Conditional on `kpti_active`:** either (a) always execute and set
  `kpti_kernel_cr3 == kpti_user_cr3 == process CR3` when inactive (a redundant
  CR3 reload per syscall — measurable, rejected for production), or (b) keep the
  current non-KPTI `syscall_entry` and install a **separate** KPTI stub as the
  `LStar` target when `kpti_active` (chosen by `init_bsp`). (b) keeps production
  untouched — prefer it. Same pattern the charter implies ("the default boot
  path installs the non-KPTI stubs").
- Preserve `SFMASK` (`syscall::init`, `:6266/:6291`) and the arg-reg contract.
- Add `KPTI_KERNEL_CR3`/`KPTI_USER_CR3`/`KPTI_SCRATCH` as `const` asm operands
  from `crate::smp::offsets` (already defined).

### A.3b — live IRQ / IST CR3 symmetry (`arch/x86_64/interrupts.rs`)

> A.3a already landed the entry-set builder + GDT/IDT/TSS mapping + reachability
> round-trip (inert). A.3b is the live asm that consumes it, **plus** the
> `cpu_entry_area` page-isolation of GDT/IDT/TSS (see the A.3a isolation caveat)
> and the per-process user-PML4 pair wiring into `new_process_page_table` /
> `AddressSpace` (the piece deferred from A.1).

Harder than A.2: on a ring-3 IRQ the CPU auto-pushes the frame to **RSP0**
(TSS) on the **user CR3** before the stub runs — so RSP0 must point at a
**per-CPU entry-trampoline stack mapped in the user PML4** (Linux `cpu_entry_area`
model), not the raw PML4[257] kstack.

**Refined design — the entry/exit-symmetry trap (derived while building A.3a; do
not repeat the mistake in this doc's older sketch).** The naïve "shim switches
CR3→kernel then `jmp`s the real `extern "x86-interrupt"` handler" is a **dead
end on the exit side.** That handler ends in the *compiler-generated* `iretq`,
which you don't control — so it returns to ring 3 with the **kernel** CR3 still
loaded. It won't crash (the user page is present in the kernel half too), so it
*looks* like it boots — but ring 3 then runs on the full kernel map and KPTI
isolates **nothing**. The exit CR3 switch has to happen *immediately before*
the `iretq`, which means owning the `iretq`. Consequences:

- **Every ring-3-reachable vector needs a naked entry+exit stub** (the
  `timer_entry` model), not a jmp-shim. Convert each `extern "x86-interrupt"`
  handler reachable from ring 3 to `extern "C"` and wrap it:
  `entry: (if from ring 3) CR3→kernel; call handler_c; (if returning to ring 3)
  CR3→user; iretq`. A shared macro pair keeps it uniform. Error-code vectors
  (`#PF`, `#GP`, `#DF`) shift the frame — the ring test reads `[rsp+16]` not
  `[rsp+8]`.
- **RSP0 = per-CPU entry stack.** The CPU pushes the frame there on the user
  CR3. **Simplification worth taking:** because maskable IRQ gates enter with
  IF=0 (no nesting) and each handler runs to completion before `iretq`, the
  stub can just run the handler **on the entry stack** after CR3→kernel (it's
  kernel-mapped too) — **no frame relocation to the process kstack needed**.
  Size the entry stack for the deepest single ring-3 handler chain (demand
  paging in `#PF`); 16 KiB is safe. Preempt handoff (`timer_handler_user`)
  already stack-switches to the scheduler stack, so it's unaffected.
- **Both naked stubs and the pure-ring0→ring3 return paths need the exit
  switch.** Full list of ring0→ring3 `iretq`/`sysretq` sites that must load the
  USER CR3 first: syscall sysret tail (✅ A.2), `enter_userspace` +
  `enter_userspace_with_retval` + `fork_enter_userspace` (`arch/x86_64/mod.rs`),
  `preempt_resume_to_user` + `timer_entry`/`reschedule_ipi_entry` user paths
  (`interrupts.rs`), `bp_entry`/`db_entry` user path, and every converted
  device/exception stub. Miss one → that path resumes ring 3 on the kernel CR3
  (silent isolation failure, not a crash — so audit, don't rely on smoke).
- **NMI + `#DF` (IST) are paranoid:** they can interrupt *either* ring, and NMI
  is the **TLB-shootdown receiver** (`nmi_handler:3347`) firing at any point,
  including inside another stub's user-CR3 window. Do **not** ring-test — read
  the current CR3, save it, switch to a known kernel CR3, restore the saved CR3
  on exit (Linux `paranoid_entry`). Their IST stacks (`gdt.rs`) must be
  user-mapped too. `read_cr3` in the stub is the reliable discriminator the
  ring test can't give you here.
- Keep `kstack-overflow-smoke` (the `#DF` path) green.
- **This is where most triple-fault debugging will live.** Build the entry set
  (GDT/TSS/IDT/entry-stacks/entry-text-section) into the real
  `new_process_page_table` user half here, and **page-isolate GDT/IDT/TSS**
  (A.3a caveat) so the stub mappings leak no adjacent `.data`.

**Kernel CR3 vs user CR3 mental model (settle this before coding A.4).** The
kernel-half CR3 = the existing per-process PML4 (full map) — the kernel already
runs on it the whole time it's in ring 0. KPTI adds only the **user-half** PML4
that ring 3 runs on. So `kpti_kernel_cr3` = the current process CR3 (unchanged);
`kpti_user_cr3` = the new user half. The dispatcher/execve/fork keep writing the
kernel CR3 as today and additionally publish the pair into `gs:[…]`; the entry
stubs switch to kernel on the way in and to user on the way out. Kernel threads
(no user half) publish `kpti_user_cr3 = 0`; the exit switch skips on zero (the
A.2 sysret tail already keys off exactly this).

## Gotchas already paid for

- **`swapgs`-free design** (above) — the single most important fact; it dictates
  the entry set and simplifies the asm vs. Linux.
- **PIE 1 TiB offset** — kernel image is `PML4[2]` (lower half), not the upper
  half; classify it explicitly or a kernel-image leak hides behind "lower half =
  user."
- **Two live `OffsetPageTable`s alias** the same direct map (`&mut PageTable`
  UB). Scope the kernel mapper (translate) to drop before building over the user
  PML4 — `mm::kpti` does this.
- **`free_process_page_table` is wrong for the KPTI user PML4** (it only frees
  USER_ACCESSIBLE leaves + PTs with user leaves, and only walks `PML4[0..256]`).
  The entry-set pages are kernel pages at `PML4[2]/[256]/[257]` with no user
  leaf → it would leak the private tables and/or skip them. A.1 sidesteps this
  with a `RecordingAlloc` (free exactly what was allocated); A.2 needs a
  dedicated user-PML4 free that frees the private entry-set sub-tables without
  touching shared kernel frames or the real entry-set leaf pages.
