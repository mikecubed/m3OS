## What landed — A.1 (this PR)

The **user-half PML4 builder** + a **boot self-test**, with `KPTI_WIRED` still
`false` (the live CR3 is untouched; every existing gate unaffected).

- **`kernel/src/mm/kpti.rs`** (new). `self_test()` (called unconditionally from
  `mitigations::init_bsp`, inside `without_interrupts`) builds a real user PML4:
  a synthetic user page at `USER_VADDR_MIN`, plus a representative **minimal
  entry set** mapped through *fresh private sub-tables* at their existing kernel
  VAs — the `PerCoreData` page(s), the `syscall_entry` text page, and a fresh
  entry stack. It walks the table back and feeds every present leaf's
  `(role, present)` to `kernel_core::kpti::check_user_half_invariant`, emitting
  `KPTI_SELFTEST:PASS`. Frees leak-free (a `RecordingAlloc` tracks exactly the
  private table frames created; the real kernel pages the entry set *points at*
  are never freed).
- **Gate** `kpti-selftest-smoke` (`M3OS_KPTI_REGRESSION=1`, `xtask` +
  `.githooks/pre-push`): boots the stock kernel, asserts `KPTI_SELFTEST:PASS`.
  Runs in ~7 s. Also documented in `docs/appendix/regression-gates.md` + the
  `AGENTS.md` gate table.
- **Proven at boot:** `KPTI_SELFTEST:PASS user_pml4=… entry_set=6 leaves; no
  kernel-secret leaf reachable from user CR3` (6 = PerCoreData spans 4 pages +
  text + stack).

**What A.1 deliberately did NOT do:** wire the builder into
`new_process_page_table` / `AddressSpace` per-process. That only earns its keep
once the CR3 switch consumes the pair; building an inert second PML4 for
every fork/exec while `KPTI_WIRED=false` is pure overhead. The `mm::kpti`
builder is the reusable piece the wiring (now A.3) calls.

## Load-bearing facts (learned mapping the kernel — do not re-derive)

1. **m3OS never executes `swapgs`.** `GS_BASE` is set directly to `PerCoreData`
   and stays that way in ring 3 (no FSGSBASE, no ring-3 `wrmsr`). The entry asm
   reads `gs:[OFFSET]` with **no swap**. Two consequences:
   - The `PerCoreData` page(s) **must** be in the user-PML4 entry set — the KPTI
     entry asm reads `gs:[kpti_kernel_cr3]` / `gs:[kpti_scratch]` *before* the
     CR3 switch. Already fields on `PerCoreData` (`kernel/src/smp/mod.rs:376–382`,
     offsets `smp::offsets::KPTI_{KERNEL_CR3,USER_CR3,SCRATCH}` at `:862–864`,
     zeroed today, read by nobody yet).
   - No swapgs ordering hazard — simpler than Linux.
2. **VA layout** (for the classifier / entry-set build):
   - User pages: VA `0x200000 .. 0x0000_8000_0000_0000` — **NOT just
     `PML4[0]`** (an earlier revision of this doc claimed that, and the error
     became the A.4 bring-up wedge). The actual user slots
     (`kernel_core::kpti::USER_PML4_SLOTS`): `PML4[0]` (ELF image + brk from
     `USER_VADDR_MIN` 0x200000, anonymous mmap from `ANON_MMAP_BASE`
     0x20_0000_0000) **and `PML4[255]`** (the stack at `ELF_STACK_TOP`
     0x7FFF_FF00_0000 − ASLR jitter).
   - Kernel image: PIE, relocated by a **fixed 1 TiB** (`0x10000000000`) → in the
     **lower half** at `PML4[2]`. (Same 1 TiB fact the Phase 111 kgdb gate uses.)
   - Heap: `0xFFFF_8000_0000_0000` = `PML4[256]`.
   - Kernel stacks: `0xFFFF_8080_0000_0000` = `PML4[257]` (`task/kstack.rs`).
   - Direct map: `phys_offset()`, some upper-half slot (compute at runtime).
3. **`mapper_for_frame(frame)`** (`mm/mod.rs:619`) builds an `OffsetPageTable`
   over an arbitrary PML4 through the direct map **without switching CR3** — the
   tool for populating the user PML4 from the BSP. `paging::get_mapper()` +
   `Translate::translate_addr` does VA→phys (scope it before building the user
   table to avoid two live `&mut PageTable` aliases).
4. **Three CR3-write loci** must all set the pair consistently once live:
   scheduler dispatch (`task/scheduler.rs:~5549`), `execve`
   (`syscall/mod.rs:~5715`), fork trampoline (`process/mod.rs:~2203`).
5. **QEMU default boot activates KPTI now that `KPTI_WIRED` is true (A.4 ✅).**
   The `[sec]` line shows `kpti(policy=true active=true)` under `Auto` because
   QEMU reports `rdcl_no=false` — **every** default gate runs the trampoline
   live, so the whole existing gate surface is the KPTI regression net. (The
   bring-up-behind-`full` idea was skipped; the flip was validated directly.)
6. **GLOBAL-bit guard already holds** (`count_global_kernel_leaf_ptes()==0`,
   asserted in `init_bsp`). Keep it; never introduce `CR4.PGE` while KPTI is on.

## What landed — A.3a (`feat/phase-110-kpti-a3a`, stacked on A.2)

The **full interrupt-delivery entry set + reachability validation**, still
inert (`KPTI_WIRED=false`):

- **Entry set grew to GDT + IDT + TSS.** On a ring-3 → ring-0 interrupt the CPU
  reads the IDT gate, the GDT descriptor for the target CS/SS, and TSS.RSP0 —
  all through the *active* (user) paging, before any handler runs. Missing any
  → delivery-time `#DF` → triple fault. `mm::kpti` now maps all three at their
  live linear addresses (`sgdt`/`sidt` for GDT/IDT; `gdt::tss_extent()` for the
  BSP TSS). New `push_kernel_range` helper (page-splits + de-dups shared pages,
  e.g. GDT+TSS adjacency).
- **Reachability round-trip** (`translate_in`): the self-test now manually
  walks the built user PML4 and asserts every entry-set page translates to the
  *same* frame the kernel map resolves — proving the trampoline's whole working
  set is present, not just that nothing extra leaked. New failure sentinel
  `KPTI_SELFTEST:FAIL reason=entry-set-unreachable`.
- **Flag split** `RX`/`RW` (entry text executable r/o; data pages NX r/w).
- **Isolation caveat — the A.3b hardening.** GDT/IDT/TSS are ordinary un-page-
  isolated kernel statics, so mapping their pages also exposes adjacent
  `.data`. Small, bounded, but a real residual Meltdown surface. A.3b must
  relocate the interrupt-delivery structures into a page-aligned entry section
  (Linux `cpu_entry_area`) — it's also the first consumer that makes the
  isolation load-bearing. Documented in the `mm::kpti` module header + tasks.
- **Green:** `check`, `kpti-selftest-smoke`.

## What landed — A.3b part 1 (`feat/phase-110-kpti-a3b`, stacked on A.3a)

The **reusable per-process user-half builder**, inert:

- **`mm::kpti::build_user_half(kernel_pml4_phys, kstack_top)`** — the function
  A.4 will load as the ring-3 CR3. Allocates a user PML4, shares `PML4[0]` with
  the kernel half (so mmap/brk/stack stay in sync — same frame, not a copy),
  and maps the entry set + this process's kstack top page through fresh private
  sub-tables (leak-free rollback on partial failure).
- **`mm::kpti::free_user_half`** — frees the private entry-set sub-tables + top
  frame; never `PML4[0]` (shared, freed by `free_process_page_table`) nor any
  leaf.
- **`collect_entry_pages`** — the shared entry set, now iterated **per online
  core** (each core's PerCoreData + GDT + TSS via
  `PerCoreData::entry_struct_extents`, BSP falling back to the global GDT/TSS)
  + the shared `.text.kpti_entry` + IDT. A process can run on any core, so all
  online cores' interrupt-delivery structures are mapped.
- **Design refinement — kstack top page instead of a separate per-CPU entry
  stack.** The CPU pushes the ring-3 IRQ frame to RSP0 on the user CR3; RSP0 =
  the process kstack top, so mapping just that **one top page** into the user
  half suffices (the stub switches to the kernel CR3 — which maps the whole
  kstack — before touching anything below it). No per-CPU trampoline stack, no
  frame relocation. Trade-off: it exposes ~4 KiB of the process's own kstack to
  itself (a small self-leak) — hardened later with a dedicated trampoline stack.
- **Self-test** now builds a real user half via `build_user_half` over a
  synthetic kernel PML4 and frees via `free_user_half` — validating the exact
  production path, not a test-only table.

**Remaining A.3b (part 2): the live IRQ/IST asm** per the blueprint below, plus
wiring `build_user_half` onto `AddressSpace` (A.4 consumes it).

## What landed — A.3b part 2 (`feat/phase-110-kpti-a3b`, the live IRQ/IST asm)

Every ring-3-reachable interrupt/exception vector became a **naked-asm entry
stub** owning its own `iretq`, so the KPTI CR3 switch can happen on the way in
*and* out. Still inert (`KPTI_WIRED=false`): every switch is a never-taken
branch (`gs:[kpti_user_cr3] == 0` on every core), so the conversion is
behaviourally identical to the old handlers and is exercised on **every boot**
by the IRQ-driven gates. Landed across four commits (2/n–5/n):

- **New section `.text.kpti_irq_entry`** (`interrupts.rs`, bottom): page-aligned
  both ends, bounded by `kpti_irq_entry_start/_end`, mapped r-x into every user
  half by `mm::kpti::collect_entry_pages` (alongside the A.2 `.text.kpti_entry`).
  All the naked stubs live physically inside it (a same-named section split
  across assembly units could land outside the bounds symbols).
- **Four asm macro pairs** (all no-ops while inactive):
  - `kpti_entry_switch` / `kpti_exit_switch` — ring-test (`cs & 3`, at `[rsp+128]`
    after the 15 GPR pushes) + active-test (`gs:[kpti_user_cr3]`) → load kernel
    CR3 in / user CR3 out. Used by the simple maskable vectors + timer/resched
    (user path) + `#BP`/`#DB`.
  - `kpti_entry_switch_err` / `kpti_exit_switch_err` — error-code frames (`#PF`,
    `#GP`): `cs` shifts to `[rsp+136]`, and the stub `add rsp, 8`s off the CPU
    error code before `iretq`.
  - `kpti_paranoid_entry` / `kpti_paranoid_exit` — **NMI + `#DF`**: they can
    interrupt *either* address space (the shootdown NMI fires at any point,
    incl. a sibling stub's user-CR3 window), so no ring test — save the entry
    CR3 in `r15` (callee-saved across the body `call`; the interrupted `r15`
    lives in the frame and is restored by `kpti_restore_gprs`), load the kernel
    CR3 when active, restore the saved CR3 on exit (Linux `paranoid_entry`).
- **Converted vectors** (all `extern "x86-interrupt" fn …_handler` →
  naked `…_entry` stub + `extern "C" fn …_body`): keyboard, serial, mouse, SCI,
  spurious, TLB-shootdown-IPI, cache-drain-IPI, the 16-slot device-MSI bank,
  `timer_entry`/`reschedule_ipi_entry` (kept their two-path ring split; CR3
  switch only on the user path), `bp_entry`/`db_entry`, `page_fault`,
  `general_protection_fault`, `nmi`, `double_fault`. IDT installs every one via
  `set_handler_addr` (NMI/`#DF` keep `set_stack_index`).
- **New frame types** (`preempt_trap_frame.rs`): `TrapFrame` (full-GPR, 5-field,
  both rings — the CPU pushes SS:RSP unconditionally in long mode) and
  `TrapFrameErr` (+ CPU error code between the GPR block and the iretq frame).
  The `#GP` body dropped its inline-asm callee-saved snapshot — `kpti_save_gprs`
  already captured the user GPRs into `frame.gprs`. The fault-kill and
  kstack-overflow redirects rewrite the frame to a **ring-0 CS**, so the exit
  switch keeps the kernel CR3 (the trampoline runs on the full map).
- **IST tops in the entry set** — the CPU switches RSP to the NMI / `#DF` IST
  top and pushes the frame there on the *user* CR3 before the paranoid stub can
  switch, so `collect_entry_pages` maps each IST stack's **top page** per online
  core (`PerCoreData::ist_top_pages` → BSP `gdt::bsp_ist_tops`, AP via `tss_ptr`).
- **`abi_x86_interrupt` feature dropped** from `kernel/src/lib.rs`: with every
  vector naked there is no `extern "x86-interrupt"` fn left in the kernel.
- **Self-test** asserts the new section is page-aligned + non-empty
  (`KPTI_SELFTEST:FAIL reason=irq-entry-layout`), and the A.3a reachability
  round-trip already proves every entry-set page (incl. the IRQ stub text + IST
  tops) is present in the built user half.
- **Green:** `check`, `smoke-test`, `kpti-selftest-smoke`, `kstack-overflow-smoke`
  (the `#PF`/`#DF` recovery + fault-kill redirect), `smp-smoke` (NMI shootdown).

**Remaining A.3b (parts 3–5):** (3) the ring0→ring3 return paths must load the
user CR3 before their `iretq`/`sysretq` — `enter_userspace` (+`_with_retval`),
`fork_enter_userspace`, `preempt_resume_to_user`, and the preempt group-exit
trampoline; (4) page-isolate GDT/IDT/TSS into a `cpu_entry_area` (close the A.3a
adjacent-`.data` leak); (5) wire `build_user_half` onto `AddressSpace` so a
per-process user PML4 exists for A.4 to publish + load.

## What landed — A.3b part 4 (`PageIsolated` / cpu_entry_area)

Closes the A.3a isolation caveat. New `gdt::PageIsolated<T>`
(`#[repr(C, align(4096))]`): align pins the page boundary AND rounds the size
to whole pages, so a static or Box of it owns its pages exclusively. Applied
to: BSP GDT/TSS/IDT statics, AP TSS+GDT heap Boxes (were the worst leak —
plain heap pages shared with arbitrary allocations), `PerCoreData` itself
(align on the struct; `smp::offsets` are `offset_of!`-computed so the gs asm
constants track), and the BSP entry stacks (`AlignedStack` 16 → 4096; the
NMI/`#DF` IST top pages are entry-set-mapped). Heap side verified: 4096/4096
Boxes land in the self-aligned 4096 slab class (a whole private page);
`PerCoreData` takes the page-backed large-alloc path. Self-test asserts page
alignment of every entry struct (`FAIL reason=entry-struct-alignment`).
Green incl. `suspend-smoke` (S3 resume reloads the relocated GDT/TSS).

## What landed — A.3b part 5 (per-process pair on `AddressSpace`)

`AddressSpace` carries `kpti_user_pml4` (0 = none): built by
`build_kpti_user_half(kstack_top)` at every address-space birth
(`spawn_process_with_cr3(+_and_fds)` — covers fork — and execve, which
rebuilds against the replacement kernel PML4), **gated on `kpti_active`** so
the inert production path builds nothing (the A.1 zero-overhead decision).
`kpti_user_pml4()` is what A.4's dispatch prep publishes to
`gs:[kpti_user_cr3]`. **Thread gotcha handled:** the half maps only the
creating task's kstack top page, but a `CLONE_VM` thread's ring-3 interrupt
frames push onto *its own* kstack top on the user CR3 — `sys_clone_thread`
maps each new thread's top page via `kpti_map_thread_kstack` →
`mm::kpti::map_kstack_top_into_user_half` (present-only change, safe while
live on a sibling core; page-table-lock serialized). Missing this = delivery
triple fault under any pthread app at A.4. `Drop for AddressSpace` frees the
half via `free_user_half` (generic `PML4[1..512]` walk covers thread-added
sub-tables; never `PML4[0]` nor leaves) — no teardown-site churn. Self-test
exercises the exact thread-add path (second stand-in kstack page +
reachability round-trip).

## What landed — A.4 (`feat/phase-110-kpti-a4`, stacked on A.3b): ACTIVATION

KPTI is **live on every default QEMU boot** (`auto` + TCG `rdcl_no=false` →
`kpti_active=true`). Two commits:

**13/n — the per-core CR3-pair publish (inert).**
`smp::publish_kpti_cr3_pair(kernel_cr3, user_cr3)`: volatile stores into the
`PerCoreData` slots, **no-op unless `kpti_active`** — the paranoid NMI/`#DF`
entry loads `kpti_kernel_cr3` whenever non-zero on EVERY interrupt, so the
slots must stay 0 on inactive boots. Published at all four loci:

- **Scheduler dispatch prep**, both branches: the URS restore (user half taken
  from the SAME `AddressSpace` as `urs.cr3_phys` — a `pml4_phys()==urs.cr3`
  filter publishes user=0 during the mid-execve transient, never consumed
  before execve republishes) and the PROCESS_TABLE fallback (pair read from
  one table entry, consistent by construction).
- **`fork_child_trampoline`**, before `enter_userspace_fork` — the first-entry
  choke point for init + every fork child.
- **execve**, right at the mid-syscall `Cr3::write(new_cr3)` (the A.2 sysret
  tail reads `gs:[kpti_user_cr3]` rather than a saved flag exactly for this).
- **`restore_kernel_cr3`** republishes `(boot PML4, 0)` — so the paranoid path
  never chases a dying process's soon-freed PML4 (every exit path calls it
  before freeing), and exit stubs stay inert on kernel-context cores.

Fail-closed on a missing user half (frame exhaustion): execve builds the half
BEFORE its destructive steps (`close_cloexec_fds`/table commit) → clean
ENOMEM; the fork trampoline kills the child (`terminate_thread_group_and_exit`,
-9) rather than entering ring 3 unisolated; `sys_clone_thread` returns ENOMEM
when the thread-kstack-top map fails.

**14/n — the flip + the user-stack-slot fix.**
- `KPTI_WIRED = true` (`mitigations.rs`); BSP LSTAR re-install
  (`syscall::reinstall_lstar()` from `lib.rs`, inside the same
  `without_interrupts` block right after `init_bsp` + self-test; APs and the
  S3-resume `init()` self-select via `lstar_target`).
- **`USER_PML4_SLOTS = [0, 255]`** (`kernel_core::kpti`): the user half now
  shares BOTH user-mapping slots with the kernel half. `build_user_half`
  clones both; `free_user_half` skips both (their sub-trees are owned by the
  kernel half); the self-test classifier + a new synthetic stack-slot leaf +
  `user-slot-unreachable` / `user-slot-overlap` failure reasons prove it.
- Gate extension: `mitigations-status-smoke` asserts
  `kpti(policy=true active=true) global_kernel_ptes=0` on the boot line and
  `Meltdown: Mitigation: PTI` from the reporter — on the DEFAULT lane (QEMU
  `auto` ≡ `full` for KPTI since TCG reports `rdcl_no=false`; the `off` /
  `RDCL_NO` arms stay host-tested in `kernel_core::spectre`).

**Plus the S3-resume trio** (found by `suspend-smoke`, which triple-faulted
after resume on the first KPTI-live run): (1) `suspend_park_and_release_aps`
no longer **frees** the AP per-core state at park — every KPTI user half maps
each core's PerCoreData/GDT/TSS/IST-top pages at their live addresses, and the
old free-and-reallocate across the S3 cycle re-created them at different
addresses, so every pre-suspend process's user half pointed at the old frames
and the first ring-3 interrupt on a resumed AP triple-faulted; (2)

guaranteed triple fault (the BSP's `gdt::reinit_after_resume` already did
this for its own TSS); (3) `collect_entry_pages` iterates every **allocated**
core (`0..MAX_CORES` + presence), not online-under-`core_count()` — suspend
shrinks `core_count` to 1 while APs are parked, and a process created on the
resumed BSP before `resume_reboot_aps` completes must still map the AP
structures.

## What landed — A.5 (`feat/phase-110-kpti-a5`, stacked on A.4): PCID / INVPCID

KPTI's TLB-cost recovery. **Dormant on every QEMU/CI lane** (TCG advertises
neither PCID nor INVPCID → `pcid_active = false` → the path reduces byte-for-byte
to A.4's full-flush); **live only on real PCID silicon** (the Dell). Two commits:

**15/n — the pure model (`kernel_core::kpti_pcid`, host-tested).** A **fixed
two-PCID scheme**: `KERNEL_PCID = 1` tags every process's kernel-half TLB
entries, `USER_PCID = 2` the user half; `CR3_NOFLUSH` (bit 63) is the no-flush
control. `compose_cr3`/`kernel_cr3`/`user_cr3` build the tagged CR3 values;
`pcid_supported(leaf1_ecx, leaf7_ebx)` gates on **both** `CPUID.01H:ECX[17]`
(PCID) and `CPUID.07H:EBX[10]` (INVPCID). 6 host tests. Buildable in isolation
(no consumer yet).

**16/n — the kernel activation.**
- **Detect + enable.** `cpuid::probe_pcid()` (both bits), `enable_pcid_if_kpti_active`
  sets `CR4.PCIDE` only when KPTI is active AND supported. Enabled on the BSP
  right after `init_bsp` + LSTAR re-install — **before `boot_aps` captures the
  CR4 into the trampoline `DATA_CR4`**, so APs inherit PCIDE (and a tagged CR3
  on a core without PCIDE would `#GP`); re-enabled on S3 resume (CR4 was reset);
  idempotently re-asserted + logged per-AP (`[sec] AP … CR4.PCIDE …`).
- **State + reporter.** `MitigationState.pcid_active = kpti_active &&
  probe_pcid()` is the single gate (`mitigations::pcid_active()`); the `[sec]`
  boot line gains `pcid(active=… supported=…)`; the D.3 report wire carries the
  bit (`b[1]` bit 6, **wire version 3**); `m3ctl mitigations status` prints a
  `KPTI PCID:` posture line (fallback vs active) when KPTI enforces.
- **The recovery — no-flush trampolines.** `smp::publish_kpti_cr3_pair` bakes the
  PCIDs + no-flush bit into the per-core `gs:[kpti_{kernel,user}_cr3]` slots when
  active, so the A.2/A.3b entry/exit stubs (which load the slots verbatim with
  `mov cr3`) do a same-process kernel↔user round trip **without** flushing — the
  two halves coexist under distinct PCIDs. The `user_cr3 == 0` kernel-thread
  sentinel stays 0 (never no-flush). Inactive → raw frames, bit 63 clear
  (mandatory: `mov cr3` with bit 63 set `#GP`s when `CR4.PCIDE = 0`).
- **Correctness across an address-space change.** `mm::write_kernel_cr3` is now
  the single dispatch/execve/fork/`restore_kernel_cr3` CR3-write locus: a
  flushing `Cr3::write_pcid(KERNEL_PCID)` load (drops the prior occupant's
  kernel-half entries under the reused global PCID) **plus** `INVPCID
  Single(USER_PCID)` (drops its user-half entries, so the exit stub's no-flush
  user load can't resurrect them). Inactive → the plain `Cr3::write(frame,
  empty())` verbatim from A.4.
- **Both-PCID invalidation (charter acceptance #2).** `smp::tlb::flush_local`
  (INVPCID Address, both PCIDs) / `flush_local_all` (INVPCID All) route the SMP
  shootdown (sender-local + IPI handler; single-addr + range + big-range) **and**
  the local CoW / spurious-write / user-page-map invlpg sites — a user-reachable
  mapping mutated on the kernel PCID would otherwise leave a stale user-PCID
  entry and loop the CoW/demand fault forever. Inactive → `invlpg` / CR3-reload.

**17/n — BSP S3-resume slot clear (bare-metal `#GP` fix, un-QEMU-testable).**
The per-core KPTI CR3-pair slots survive S3 in RAM holding **PCID-tagged**
values (bit 63 no-flush set), but the machine reset clears `CR4.PCIDE`. In the
resume window before PCIDE is re-enabled, a paranoid NMI/`#DF` — which loads
`kpti_kernel_cr3` whenever nonzero — would `mov cr3` a bit-63 value with
PCIDE=0 and `#GP`. `smp::clear_kpti_cr3_slots()` zeroes the BSP's slots right
after `restore_bsp_gs_base()` (the paranoid path then skips its load until the
first post-resume dispatch republishes with PCIDE on). The AP re-boot path
(`init_ap_per_core`) already zeroes the slots before an AP's IDT loads, so only
the BSP needed it. No-op on the inactive/QEMU lane. Green: `check`,
`suspend-smoke`. *(General rule reinforced: on any path that clears `CR4.PCIDE`
— reset/resume/hotplug — the tagged CR3 slots must be zeroed before an NMI can
load them, since bit 63 is reserved-`#GP` while PCIDE is off.)*

## What landed — post-A.5 hardening (`feat/phase-110-kpti-hardening`, PR #324): the per-CPU trampoline stack

Closes the A.3b accepted self-leak (the task-kstack **top page** — live
interrupt frames with kernel RIP/RSP values — was mapped into the process's
own user half) and deletes the per-thread `CLONE_VM` kstack map. The m3OS
`cpu_entry_area` entry stack, in four commits:

- **18/n — the stack itself (inert).** `PerCoreData.kpti_tramp_top`: an 8 KiB
  per-core stack (raw page-aligned `alloc_zeroed` — same isolation as
  `PageIsolated`, no debug-build stack-intermediate hazard) whose **top page**
  joins the shared entry set; the page below is kernel-only spillover for a
  should-never-happen ring-0 fault while `rsp` is on it. Address-stable
  forever (S3 reuse keeps it — the "anything a user half maps must be
  address-stable" rule; `release_failed_ap` reclaims it). Plus
  `kpti_scratch2` (the exit copy's second spill slot) and self-test arms
  (`kpti-tramp-top` alignment + entry-set reachability).
- **19/n — RSP0 → trampoline stack + entry copy.** When `kpti_active`,
  `smp::set_current_core_kernel_stack` (the single RSP0 choke point every
  dispatch locus calls) redirects RSP0 to `kpti_tramp_top`; callers still
  publish the task kstack top to `gs:[SYSCALL_STACK_TOP]`. Ring-3 frames land
  on the trampoline stack on the user CR3; after the entry CR3 switch,
  `kpti_copy_frame_to_kstack` copies the 20/21-qword block (15 GPRs +
  [error code +] iretq frame) to `gs:[SYSCALL_STACK_TOP]-160/168` — the exact
  pre-hardening address — and pivots, so bodies/preempt-capture/fault
  redirects see a byte-identical machine state. The paranoid non-IST vectors
  (`#PF`/`#GP`/`#BP`/`#DB`) use `kpti_entry_copy_if_user` (their CR3 load is
  not ring-gated, so the copy carries its own ring-3 + published-user-CR3
  test). NMI/`#DF` (IST) untouched. The `cld` before `rep movsq` is
  load-bearing: ring 3 controls DF at delivery.
- **20/n — exit frames on the trampoline stack.** Combined
  `kpti_exit_iretq`/`_err` macros: on a ring-3 + active return, `cli` → pop
  GPRs on the KERNEL CR3 from the kstack copy → copy the 5-word iretq frame
  to the trampoline stack via the two per-core scratch slots → pivot → flip →
  `iretq`. The `cli` is load-bearing twice over: the copy parks live values
  in persistent per-core state (a preemption could migrate cores or let
  another task's syscall clobber `kpti_scratch`), and it closes the
  previously-implicit "bodies return with IF=0" assumption (`page_fault_body`
  can `sti` for demand paging). The cs re-test keeps the fatal-fault
  redirects working (ring-0-rewritten frames take the plain pop-in-place
  branch). The four `.text.kpti_exit` trampolines pivot to
  `gs:[kpti_tramp_top]` unconditionally (slot populated on every lane).
- **21/n — drop the kstack mapping (the payoff).** `build_user_half` loses
  its `kstack_top` arg (the user half is now fully process-independent apart
  from the shared `USER_PML4_SLOTS`); `map_kstack_top_into_user_half` +
  `AddressSpace::kpti_map_thread_kstack` + the `sys_clone_thread` ENOMEM arm
  are **deleted**; the self-test gains the `kstack-reachable` negative
  round-trip (the pre-hardening page must NOT translate in the user half).
  No kernel-stack page is reachable from any user CR3.

**Inactive lane** (`mitigations=off` / `RDCL_NO`): RSP0 stays the task kstack
top and every new branch falls through — behaviourally identical to A.5.

**Green (per commit):** `check`, `kpti-selftest-smoke`, `smoke-test`,

### The two remaining follow-ups (`feat/phase-110-kpti-hardening2`, PR #325)

- **22/n — `#PF`-time top-level-slot sync (Linux vmalloc-fault analogue).**
  Closes the latent wedge the "gotchas" list flagged: a `USER_PML4_SLOTS`
  entry EMPTY in the kernel half at pair-build time is cloned empty into the

- **23/n — same-address-space re-dispatch CR3 skip.** `mm::write_kernel_cr3`

  hold frame `F` now, the space whose PML4 is `F` is live on this core → `F`
  can't have been freed+reallocated to a different space (live PML4 frames are
  never reused) → "current == target" ⟺ the same live space, which has had

  relies on the dispatch reload (demand paging skips shootdowns by the
  not-present rule; munmap/mprotect/CoW issue their own). A real switch always
  differs (execve allocates a fresh PML4 while the old is live; fork copies the
  table) and is never skipped. The skipped `INVPCID USER_PCID` only matters on
  a cross-process switch, which a same-frame re-dispatch is not. Recovers the
  idle→same-task and repeated-same-task dispatch flush cost on every lane
  (the PCID no-flush win is A.5; this is the orthogonal switch-in flush).

## Resolved bug — intermittent `#DF` in `page_fault_body`

**Symptom.** The full `regression` suite fails intermittently (~1 test/run;
the failing test *varies*: `pty-overlap`, `kbd-echo`, `serverization-fallback`,
`service-lifecycle`…), always as "kernel crash detected during step 1 (wait
for final boot marker)" — i.e. a boot-time kernel fault during init's service
spawn, under the suite's back-to-back QEMU load. Solo runs and one full re-run
were green, so it is **timing/contention-sensitive**. Not present in the
committed 13/n (all switches inert); introduced by the 14/n **flip** (switches
now live).

**Captured crash** (`service-lifecycle` artifact,
`target/regression/<test>/serial.log`): `DOUBLE FAULT`, `rip=0x10000dd2380`
which `nm` resolves to **exactly `page_fault_body`** (subtract the 1 TiB PIE
base → `0xdd2380`). `CR3=0x5d82000` (a process **kernel** half — the `#DF`'s
own paranoid entry loaded `kpti_kernel_cr3`), **`r15=0x5db8000`** (the CR3 that
was active when the `#DF` was delivered — a **user half**, a partial map).
`CR2=0xffff8080…` (a `PML4[257]` kstack-region address, unmapped in the user
half).

**Diagnosis (high confidence).** `page_fault_body` executed **on the user-half
CR3** and faulted touching general kernel memory (a kstack page absent from the
user half); the nested fault couldn't be delivered → `#DF`. It ran on the user
half because the `#PF` entry stub `page_fault_entry` uses **`kpti_entry_switch_err`
(the ring test)**, which *skips* the CR3 switch when the fault came from ring 0
(`cs & 3 == 0`). But a ring-0 fault **can** occur while a trampoline transiently
holds the user CR3 (the entry/exit stub windows where we are in ring 0 with
`CR3 = user`). The register evidence is decisive: `kpti_kernel_cr3` was valid
at the time (the `#DF` paranoid entry successfully loaded `0x5d82000`), so a
**paranoid** `#PF` entry would have loaded that same kernel CR3 and run
`page_fault_body` on the full map — no fault.

**The bug is two mechanisms; the fix is two complementary changes** (both in
`interrupts.rs`). The *root cause* is a genuine **IF=1 ring-0/user-CR3 window**:
the `execve`/`sigreturn`/`fork` exit trampolines flip `CR3 → user` and then run
several instructions (frame build, GPR restore, `iretq`) still in ring 0 on the
user half. Those three syscalls reach the trampoline with **IF=1** (the
syscall's `SFMASK` cleared IF, but they re-enable it doing blocking IPC / disk /
scheduler work), so a maskable **timer/reschedule IPI** delivered in that window
vectors to its naked stub, sees the interrupted **ring-0** `cs`, takes the
"ring 0 ⟹ already on kernel CR3" kernel path (which does **no** CR3 switch), and
`call`s its `.text` body — which is absent from the user half →
`INSTRUCTION_FETCH` `#PF` → nested-fault `#DF`. (`dispatch_preempted_and_resume`
already `cli`s before `preempt_resume_to_user`, which is why the preempt path
never triggered it.)

**Fix 1 (root cause) — `cli` in all four exit trampolines** before the CR3
flip, so the flip→`iretq` window runs IF=0 (the `iretq` restores the task's own
IF from the frame). This closes the maskable-IPI delivery path into the window,
uniform with the syscall sysret tail (`cli`) and the preempt path.

**Fix 2 (defense-in-depth + observability) — paranoid `#PF`/`#GP`/`#DB`/`#BP`
entry.** These four exception vectors now use **`kpti_paranoid_entry`** (read
the actual CR3, load `kpti_kernel_cr3` unconditionally) instead of the ring-test
entry macros, so their body always runs on the full kernel map regardless of
how they were entered. This is needed independently of fix 1 for the
*synchronous* window faults `cli` can't block — a non-canonical `iretq`/`sysretq`
raising `#GP`/`#SS`, or a `#DB` single-step (debug builds) — and it is what made
the diagnosis possible: with paranoid entry, `page_fault_body` runs cleanly and
*names the culprit* (`INSTRUCTION_FETCH` at `reschedule_ipi_handler_kernel`)
instead of `#DF`-ing on the user half. **The exit stays `cs`-based**
(`kpti_exit_switch{,_err}`), NOT paranoid: the `#PF`/`#GP` bodies redirect a
*fatal* fault by rewriting `frame.cs` to a ring-0 kill trampoline
(`page_fault_body` / `try_recover_kstack_overflow`), and the `cs`-based exit
keeps the kernel CR3 for that ring-0 target — a paranoid exit would restore the
saved (user) CR3 and run the kill trampoline unisolated. Cost: one extra CR3
load per fault when KPTI is active (the KPTI tax; PCID recovery is A.5).

**Causation was confirmed** before the fix: a `M3OS_MITIGATIONS=off` regression
run (KPTI dormant → every CR3 switch a no-op) passed **11/11**, and the register
evidence is conclusive on its own — a **user-half CR3** only exists / is only
loaded when KPTI is active, and `page_fault_body` was observed running on one.
The static asm audit confirmed the macro-per-vector table and that the
trampolines have no operand-ordering bug (the window is entered by *delivery*,
not by a window instruction faulting).

**Post-fix validation (all green):** `check`, `kstack-overflow-smoke` (the
`#PF`/`#DF` recovery + ring-0 redirect path — most affected), `kpti-selftest-smoke`,
`smoke-test`, `suspend-smoke`, `mitigations-status-smoke`, and the full
`regression` suite **4× back-to-back (11/11 each)** — the `#DF` was
contention/timing-sensitive (~1 fail/run before the fix), so four consecutive
clean runs is the confidence bar. **Resolved.**

**Uniform recipe for each `iretq` trampoline** (mirrors the A.2 sysret tail, which
is the proof-of-pattern):

1. **Move it into a user-mapped section** — a new `.text.kpti_exit` (page-aligned,
   bounded by `kpti_exit_start/_end`, mapped `RX` by
   `mm::kpti::collect_entry_pages` exactly like `.text.kpti_irq_entry`). The
   instructions from the `mov cr3` through `iretq` must be user-mapped, so the
   whole trampoline goes in the section.
2. **`mov rsp, gs:[OFF_STACK_TOP]`** — reset to the task's kstack **top page**
   (user-mapped). Safe: all four are `-> !` and build a fresh frame; nothing below
   is needed (execve/fork/sigreturn start fresh; the preempt path already saved
   the scheduler RSP in `dispatch_preempted_and_resume` before the `jmp`).
3. **Build the 5-field `iretq` frame** (`push ss/rsp/rflags/cs/rip`) from the
   path's reg source — lands in `[STACK_TOP-40, STACK_TOP)`, still the top page.
4. **Restore all GPRs from the reg source BEFORE the CR3 switch** — the source
   (`PreemptFrame`/`ForkEntryCtx`/`SavedUserRegs`) lives in the kernel map, gone
   after the flip. (`ForkEntryCtx` is in PerCoreData → mapped both halves, so
   fork could switch earlier, but keep it uniform.)
5. **CR3 switch via the scratch slot** (rax now holds a user value):
   `mov gs:[OFF_KPTI_SCRATCH], rax; mov rax, gs:[OFF_KPTI_USER_CR3]; test rax,rax;
   jz 1f; mov cr3, rax; 1: mov rax, gs:[OFF_KPTI_SCRATCH]` — no-op while inactive
   (`kpti_user_cr3 == 0`).
6. **`iretq`.**

`enter_userspace` / `restore_and_enter_userspace` are inline `asm!` in Rust `-> !`
fns today; convert each to call a `global_asm` trampoline in the section (pass
`entry`/`rsp` or the `SavedUserRegs` ptr in a register). `preempt_resume_to_user`
and `fork_enter_userspace` are already `global_asm` — move + augment in place.
Delete the dead `enter_userspace_with_retval` (or convert for completeness).

**Testing (all inert — switches are no-ops):** every process start (execve),
`fork`, preemption, and signal exercises these on every boot, so `smoke-test` +
`kstack-overflow-smoke` + a fork/signal-heavy run are the net. Because the
rsp-reset + frame-relocation are *behavioral* changes (not just the no-op CR3
switch), a mistake shows up immediately as a boot/exec/fork failure.

**⚠ Highest-risk asm in the whole track** — 5 of the kernel's most critical
paths. Do it as its own focused pass (per-path sub-commits: preempt first, then
fork, then execve, then sigreturn), not at the tail of a long session.

### A.2 — syscall-entry CR3 trampoline (`arch/x86_64/syscall/mod.rs`) ✅

The `syscall_entry` `global_asm` (`:1132–1314`). SYSCALL does **no** automatic
stack/CR3 switch, so the stub owns everything — no trampoline stack needed for
this path (nothing is auto-pushed):

```asm
; entry: user CR3 active, rcx=user rip, r11=user rflags, rax=syscall nr, no swapgs
mov gs:[OFF_USER_RSP], rsp          ; PerCoreData is user-mapped → OK on user CR3
mov gs:[OFF_KPTI_SCRATCH], rax      ; spill syscall nr (PerCoreData writable, user CR3)
mov rax, gs:[OFF_KPTI_KERNEL_CR3]
mov cr3, rax                        ; → kernel CR3 (PerCoreData mapped in BOTH halves)
mov rax, gs:[OFF_KPTI_SCRATCH]      ; restore syscall nr
mov rsp, gs:[OFF_STACK_TOP]         ; NOW safe: real kstack (PML4[257]) is kernel-only
… existing body …
; exit tail (after `mov rsp, gs:[OFF_USER_RSP]`, before sysretq):
mov rax, gs:[OFF_KPTI_USER_CR3]     ; but rax holds the return value → spill/restore via scratch
mov gs:[OFF_KPTI_SCRATCH], rax … mov cr3, …  ; → user CR3, then sysretq
```
- **Conditional on `kpti_active`:** either (a) always execute and set
  `kpti_kernel_cr3 == kpti_user_cr3 == process CR3` when inactive (a redundant
  CR3 reload per syscall — measurable, rejected for production), or (b) keep the
  current non-KPTI `syscall_entry` and install a **separate** KPTI stub as the
  `LStar` target when `kpti_active` (chosen by `init_bsp`). (b) keeps production
  untouched — prefer it. Same pattern the charter implies ("the default boot
  path installs the non-KPTI stubs").
- Preserve `SFMASK` (`syscall::init`, `:6266/:6291`) and the arg-reg contract.
- Add `KPTI_KERNEL_CR3`/`KPTI_USER_CR3`/`KPTI_SCRATCH` as `const` asm operands
  from `crate::smp::offsets` (already defined).

### A.3b — live IRQ / IST CR3 symmetry (`arch/x86_64/interrupts.rs`)

> A.3a already landed the entry-set builder + GDT/IDT/TSS mapping + reachability
> round-trip (inert). A.3b is the live asm that consumes it, **plus** the
> `cpu_entry_area` page-isolation of GDT/IDT/TSS (see the A.3a isolation caveat)
> and the per-process user-PML4 pair wiring into `new_process_page_table` /
> `AddressSpace` (the piece deferred from A.1).

Harder than A.2: on a ring-3 IRQ the CPU auto-pushes the frame to **RSP0**
(TSS) on the **user CR3** before the stub runs — so RSP0 must point at a
**per-CPU entry-trampoline stack mapped in the user PML4** (Linux `cpu_entry_area`
model), not the raw PML4[257] kstack.

**Refined design — the entry/exit-symmetry trap (derived while building A.3a; do
not repeat the mistake in this doc's older sketch).** The naïve "shim switches
CR3→kernel then `jmp`s the real `extern "x86-interrupt"` handler" is a **dead
end on the exit side.** That handler ends in the *compiler-generated* `iretq`,
which you don't control — so it returns to ring 3 with the **kernel** CR3 still
loaded. It won't crash (the user page is present in the kernel half too), so it
*looks* like it boots — but ring 3 then runs on the full kernel map and KPTI
isolates **nothing**. The exit CR3 switch has to happen *immediately before*
the `iretq`, which means owning the `iretq`. Consequences:

- **Every ring-3-reachable vector needs a naked entry+exit stub** (the
  `timer_entry` model), not a jmp-shim. Convert each `extern "x86-interrupt"`
  handler reachable from ring 3 to `extern "C"` and wrap it:
  `entry: (if from ring 3) CR3→kernel; call handler_c; (if returning to ring 3)
  CR3→user; iretq`. A shared macro pair keeps it uniform. Error-code vectors
  (`#PF`, `#GP`, `#DF`) shift the frame — the ring test reads `[rsp+16]` not
  `[rsp+8]`.
- **RSP0 stays the process kstack; map only its top page (decided + built in
  A.3b part 1).** No separate per-CPU entry stack. The CPU pushes the ring-3
  IRQ frame to RSP0 = the process kstack top on the user CR3; `build_user_half`
  maps just that **top page** into the user half, and the stub switches to the
  kernel CR3 (which maps the whole kstack) before touching anything below it —
  so no frame relocation is needed, and the handler runs on the real kstack as
  today. Because maskable IRQ gates enter with IF=0, there's no nesting on that
  top page before the CR3 switch. (Trade-off: exposes ~4 KiB of the process's
  own kstack to itself — hardened later with a dedicated trampoline stack.)
- **⚠ Fault-recovery paths are entangled — audit each, they are NOT covered by
  the generic macro.** `interrupts.rs` has non-obvious control flow the CR3
  conversion must handle by hand: (1) the **kstack-overflow** recovery — a #PF
  on a near-exhausted kstack `iretq`s into `fault_kill_trampoline` on a
  **per-core recovery stack** (`FAULT_RECOVERY_STACK`), and a guard-page hit
  escalates to **#DF** on the DF IST stack that runs the kill directly; both
  the recovery stack and the redirect `iretq` need CR3 awareness (the recovery
  stack must be reachable on whatever CR3 is live, and the redirect-to-ring0
  `iretq` must NOT switch to the user CR3). (2) `fault_kill_trampoline` switches
  stacks itself. (3) the `#PF`/`#GP` → `fault_kill` two-phase path. Map the
  per-core recovery + IST stacks into the entry set (or ensure the redirect
  stays on the kernel CR3), and keep `kstack-overflow-smoke` green — it
  exercises exactly this.
- **Both naked stubs and the pure-ring0→ring3 return paths need the exit
  switch.** Full list of ring0→ring3 `iretq`/`sysretq` sites that must load the
  USER CR3 first: syscall sysret tail (✅ A.2), `enter_userspace` +
  `enter_userspace_with_retval` + `fork_enter_userspace` (`arch/x86_64/mod.rs`),
  `preempt_resume_to_user` + `timer_entry`/`reschedule_ipi_entry` user paths
  (`interrupts.rs`), `bp_entry`/`db_entry` user path, and every converted
  device/exception stub. Miss one → that path resumes ring 3 on the kernel CR3
  (silent isolation failure, not a crash — so audit, don't rely on smoke).
- **NMI + `#DF` (IST) are paranoid:** they can interrupt *either* ring, and NMI
  is the **TLB-shootdown receiver** (`nmi_handler:3347`) firing at any point,
  including inside another stub's user-CR3 window. Do **not** ring-test — read
  the current CR3, save it, switch to a known kernel CR3, restore the saved CR3
  on exit (Linux `paranoid_entry`). Their IST stacks (`gdt.rs`) must be
  user-mapped too. `read_cr3` in the stub is the reliable discriminator the
  ring test can't give you here.
- Keep `kstack-overflow-smoke` (the `#DF` path) green.
- **This is where most triple-fault debugging will live.** Build the entry set
  (GDT/TSS/IDT/entry-stacks/entry-text-section) into the real
  `new_process_page_table` user half here, and **page-isolate GDT/IDT/TSS**
  (A.3a caveat) so the stub mappings leak no adjacent `.data`.

**Kernel CR3 vs user CR3 mental model (settle this before coding A.4).** The
kernel-half CR3 = the existing per-process PML4 (full map) — the kernel already
runs on it the whole time it's in ring 0. KPTI adds only the **user-half** PML4
that ring 3 runs on. So `kpti_kernel_cr3` = the current process CR3 (unchanged);
`kpti_user_cr3` = the new user half. The dispatcher/execve/fork keep writing the
kernel CR3 as today and additionally publish the pair into `gs:[…]`; the entry
stubs switch to kernel on the way in and to user on the way out. Kernel threads
(no user half) publish `kpti_user_cr3 = 0`; the exit switch skips on zero (the
A.2 sysret tail already keys off exactly this).

## Discovered (unrelated to KPTI) — pre-existing `smp-smoke` node crash ✅ RESOLVED (PR #323)

While validating A.3b part 2, `smp-smoke` was found **red** and confirmed
**pre-existing** (reproduces identically with KPTI inert on `main` and active on
A.4/A.5 — the CR3/TLB path is not involved). Under the futex-heavy node
threadpool stress (256 async pbkdf2) a V8 `# Check failed: 12 ==
(*__errno_location())` fires, then `int3` → `#GP` (IDT[3] DPL 0 without
`ptrace`) → the kernel kills the process.

**The original diagnosis here was WRONG** ("an SMP-path syscall returning the
wrong error/errno, or a TLS/errno write racing an interrupt"). Root-caused by
instrumenting the mmap/mprotect dispatch to log non-ENOMEM error returns:

```
[smpdbg] mprotect FAIL pid=46 addr=0x2000cc3000 len=0x3c000 prot=0x7 -> errno 22
```

`prot=0x7` = **PROT_READ|WRITE|EXEC**. The pbkdf2 loop is hot enough that V8
tiers it up and **JIT-compiles** it, then requests a **W+X** mapping for its
code space. m3OS's **W^X** enforcement correctly rejects `mprotect(RWX)` with
**EINVAL** on the no-PKU TCG lane (W^X v1, no pkey-guarded W+X) — the kernel is
right — but V8's `OS::SetPermissions` does `CHECK_EQ(ENOMEM, errno)` and
hard-aborts on any non-ENOMEM failure. So it is a **deterministic W^X-vs-JIT
conflict**, not an SMP scheduler/errno bug at all. (`errno == ENOMEM` would have
been *tolerated* — the `12 ==` in the message is `CHECK_EQ(ENOMEM, errno)` after
two-level macro expansion, not the kernel returning 12.)

**Fix (PR #323, on `fix/smp-smoke-jitless` off `main`):** pin the stress
`node -e` to `--jitless` so V8 runs Ignition-only and emits zero W+X mappings —
the gate then exercises its real target (the libuv-threadpool ↔ event-loop
futex handshakes) without the JIT crash, deterministically. Validated green at
`-smp 2` and `-smp 8`. JIT node is the separate `node-jit-smoke` gate
(KVM + PKU, where W^X v2 makes RWX legal). **Follow-up:** the jitless node
port's baked-in `--v8-options=--jitless` default does not take effect in the
installed binary (plain `node` JITs; only the runtime `--jitless` flag
suppresses W+X) — a node-port pass to make bare `node script.js` W^X-safe by
default is worthwhile but needs rebuild cycles. (Handy:
`M3OS_SMOKE_SERIAL_DUMP=<path>` dumps the full guest serial on any smoke
failure.)

## Gotchas already paid for

- **Ring 0 on the user CR3 must run with IF=0 (the A.4 `#DF` wedge).** The
  KPTI exit trampolines are ring 0 on the *user* half between their `mov cr3,
  user` and `iretq`. That window must be IF=0 or a maskable timer/reschedule
  IPI fires, sees the ring-0 `cs`, takes its "already-kernel-CR3" fast path
  (no switch), and `call`s its `.text` body — absent from the user half →
  `INSTRUCTION_FETCH` `#PF` → `#DF`. `execve`/`sigreturn`/`fork` reach their
  trampolines with **IF=1** (they re-enabled during blocking work after the
  syscall's `SFMASK` cleared it), so they needed an explicit `cli`
  (`preempt_resume_to_user` was already covered by `dispatch_preempted_and_resume`).
  General rule: **any code that runs ring 0 on the user CR3 must have IF=0 and
  must not `call` into non-entry-set `.text`.** The complementary rule for the
  *fault* vectors that can still fire there (a bad `iretq`/`sysretq` `#GP`, a
  `#DB` single-step): make them **paranoid** (read+load the kernel CR3), never
  ring-test — the CS ring-test assumes "ring 0 ⟹ kernel CR3", which the windows
  violate.
- **S3 resume re-allocated the AP per-core structures (the A.4 suspend
  wedge).** The suspend park *freed* each AP's PerCoreData (GDT/TSS/IST
  leaked) and resume re-allocated at different addresses — but every existing
  user half maps those structures at their **pre-suspend** addresses, so the
  first ring-3 interrupt on a resumed AP read an unmapped GDT on the user CR3
  → `#PF` → `#DF` (new IST top also unmapped) → triple fault
  (`suspend-smoke` died waiting for `POWERD:resume`). Fixed by keeping the
  allocations across S3 + in-place reuse in `init_ap_per_core` — which then
  exposed the second S3 classic: the reused GDT's TSS descriptor still
  carried the **busy bit** from the pre-suspend `ltr`, and the AP re-boot
  `ltr`s before its IDT is loaded → #GP → triple fault. Clear bit 41 like the
  BSP's `reinit_after_resume`. Rule of thumb: **anything a user half maps must
  be address-stable for the life of every process** — S3, and any future
  hotplug/re-init path, must reuse, never re-allocate.
- **The user stack lives in `PML4[255]`, not `PML4[0]` (the A.4 bring-up
  wedge).** `build_user_half` originally shared only `PML4[0]`, following this
  doc's (then-wrong) "user pages = PML4[0]" fact — but `ELF_STACK_TOP` is
  `0x7FFF_FF00_0000` → slot 255. First live boot: kernel + init loaded fine,
  then userspace went silent — **no crash, no triple fault, no log**. The
  first ring-3 stack access #PF'd on the user CR3; the handler (on the kernel
  CR3, where the mapping exists) found nothing wrong and `iretq`'d back; the
  access re-faulted forever. Diagnosis: `M3OS_SMOKE_SERIAL_DUMP` showed boot
  stopping exactly at "init registered as pid 1", and `rsp=0x7ffffefc8ee0` in
  the load log names slot 255 directly. Fix: `USER_PML4_SLOTS = [0, 255]`
  shared verbatim (and skipped by `free_user_half` — its sub-trees are the
  kernel half's to free). Residual hazard to remember: a user mapping in a
  top-level slot that is EMPTY at pair-build time (or outside the shared set,
  e.g. a far MAP_FIXED) exists only in the kernel half → that process wedges
  in the same silent #PF loop. All current layouts pre-populate both slots
  before the pair is built; a `#PF`-time top-level-slot sync (Linux
  vmalloc-fault style) is the hardening follow-up if the layout ever grows.
- **`swapgs`-free design** (above) — the single most important fact; it dictates
  the entry set and simplifies the asm vs. Linux.
- **PIE 1 TiB offset** — kernel image is `PML4[2]` (lower half), not the upper
  half; classify it explicitly or a kernel-image leak hides behind "lower half =
  user."
- **Two live `OffsetPageTable`s alias** the same direct map (`&mut PageTable`
  UB). Scope the kernel mapper (translate) to drop before building over the user
  PML4 — `mm::kpti` does this.
- **`free_process_page_table` is wrong for the KPTI user PML4** (it only frees
  USER_ACCESSIBLE leaves + PTs with user leaves, and only walks `PML4[0..256]`).
  The entry-set pages are kernel pages at `PML4[2]/[256]/[257]` with no user
  leaf → it would leak the private tables and/or skip them. A.1 sidesteps this
  with a `RecordingAlloc` (free exactly what was allocated); A.2 needs a
  dedicated user-PML4 free that frees the private entry-set sub-tables without
  touching shared kernel frames or the real entry-set leaf pages.
